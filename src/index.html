The checker reads the file line by line and reports structure problems, bad dates and numbers, codes that are not in CIC’s tables, duplicate subjects and contracts, and a footer count that does not match.

CodeDescription

  1. Name and save the text file

    <ProviderCode>_CSDF_<YYYYMMDDhhmmss>.txt, for example BANK1234_CSDF_20150130143010.txt. The provider code is the 8-character code CIC assigned; the timestamp is when the file was created, in 24-hour time. Save as UTF-8 without BOM, pipe-delimited, with the label rows removed.

  2. Zip it

    Right-click the text file → Send to → Compressed (zipped) folder. One text file per zip.

  3. Encrypt the zip with Kleopatra

    Sign/Encrypt Files → select the zip → tick only Encrypt for others and pick “Credit Information Corporation”. Untick Sign as and Encrypt for me, then Encrypt. Testing and Production use different keys; the Production key is renewed every year.

  4. Upload the .gpg or .pgp file

    Open the web client at mftp.creditinfo.com.ph/webclient/WebClient.xhtml, log in and enter the 6-digit code e-mailed to you. Go to SUBMISSION → INPUT and upload. A “File was Successfully Uploaded” e-mail confirms it.

  5. File the transmittal

    CE Portal → Transmittal Module → Pending Transmittals → + File transmittal. Enter the covered period, the submission type and the record counts per type. The Results tab shows those counts for the file you checked. Only the Primary Contact Person can open this module.

  6. Collect CIC’s result

    Download it from SUBMISSION → OUTPUT. CIC validates in three phases: PRE (file structure), CPS/CPC (checking of subject and contract records) and LPS/LPC (loading into the database).

Dates to keep in mind

  • Regular submissions are monthly and due on the 10th day of the following month.
  • A request for extension can only be filed from the 1st to the 10th of the month, for that month’s regular submission.
  • Correction files answer an Output Error Report within 15 working days; dispute corrections within 5 working days of the notice.
  • Special submissions (corrections, disputes, delayed or historical data) go in their own file, never mixed into the regular one.

Each finding carries a rule code. CIC manual rules come from the CIC session materials and the “Fields in Excel” workbook. Sanity check rules are sensible checks that those materials do not spell out, so treat them as prompts to look, not as CIC’s verdict.
